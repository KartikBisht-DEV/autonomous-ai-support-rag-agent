B.Tech CSE Placement Interview & Viva Guide

Quick cheat sheet, system design justification, mathematical formulas, and top 10 interviewer questions

1-Minute Elevator Pitch (Say this in interview)

"I built an Autonomous AI Support Agent with RAG to solve enterprise customer support hallucination. The system implements a 4-stage pipeline: First, it ingests raw policy PDFs and applies sliding-window recursive chunking (350 tokens, 60 overlap) to preserve semantic boundaries. Second, it computes high-dimensional vector embeddings and indexes them in a Cosine Vector Store with hybrid BM25 keyword reranking. Third, an Agentic Brain uses a ReAct loop to classify user intent, autonomously invoke backend tools (like live order lookup, refund calculations, and SLA ticket escalations), and verify fact-grounding. Finally, it synthesizes factual responses with full source citations and live thought tracing."

Mathematical & Algorithmic Foundations

1. Cosine Similarity Formula
Cosine(u, v) = (u • v) / (||u||₂ * ||v||₂)

Calculates the angular distance between normalized high-dimensional query and document vectors, invariant to text length.

2. Sliding Window Chunking
Step = ChunkSize (350) - Overlap (60) = 290

60-token overlap prevents sentences from being severed mid-thought across adjacent chunk boundaries.

3. Time & Space Complexity
Search Time: O(N * D) | Memory: O(N * D)

Where N = number of indexed chunks, D = embedding dimension (256 dense features).

Top Interview Questions & Ready Answers

Q1: Why did you choose RAG instead of Fine-Tuning an LLM?

Answer: Fine-tuning updates model weights for style/format, but is expensive, slow to update, and still hallucinates on dynamic facts. RAG separates knowledge retrieval from reasoning: policy updates only require re-indexing a PDF in the Vector DB without retraining. It also provides verifiable source citations.

Q2: How does the ReAct Agent decide whether to call a tool or search the knowledge base?

Answer: The orchestrator implements a multi-step ReAct loop: First, it runs intent & entity classification. If an Order ID (ORD-XXXX) is detected, it triggers lookup_order. If refund intent is present, it computes eligibility against the 30-day return policy. If low confidence or high outage sentiment is detected, it executes escalate_ticket.

Q3: How do you prevent LLM hallucinations?

Answer: We enforce three guardrails: (1) Prompt grounding constraint instructing the model to answer only from retrieved context chunks, (2) Grounding confidence scoring that measures semantic alignment, and (3) Source document citation linking.

Q4: Why FastAPI over traditional Flask or Django?

Answer: FastAPI is built natively on ASGI (Starlette + Uvicorn) providing asynchronous non-blocking I/O, which is essential when awaiting external LLM API calls and vector calculations. It also offers automatic Pydantic schema validation and Swagger docs.

Q5: How would you scale this system for 10 Million enterprise documents?

Answer: Replace exact brute-force cosine matrix search with Approximate Nearest Neighbor (ANN) indexing like HNSW (Hierarchical Navigable Small World) in a distributed vector database (e.g. Pinecone, Milvus, Qdrant). Move document ingestion to Celery background task workers with Redis queues.
